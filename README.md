# LUME — Практична робота №5

## Тема

Створення адаптивного вебінтерфейсу за допомогою Flexbox, CSS Grid і media queries.

## Опис проєкту

LUME — навчальний вебсайт магазину смарт-речей для дому. Проєкт продовжує практичні роботи №2–4 та містить головну сторінку, форми входу, реєстрації й створення товару.

У практичній роботі №5 інтерфейс адаптовано для вузьких і широких екранів. Збережено семантичну HTML-структуру, логічний порядок елементів і валідацію форм.

## Адаптивна верстка

Використано підхід **mobile-first**: базові стилі задають вертикальне розташування блоків, а media queries додають складнішу композицію на ширших екранах.

- **Flexbox** використано для навігації, пошуку, груп кнопок і рядків checkbox/radio. Перенесення налаштовано через `flex-wrap`, відступи — через `gap`.
- **Grid** використано для каталогу товарів і головного інформаційного блоку. Каталог автоматично змінює кількість колонок:

```css
grid-template-columns: repeat(auto-fit, minmax(min(100%, 15rem), 1fr));
```

- Контейнер має гнучку ширину й максимальне обмеження. Для розмірів тексту та відступів використано `clamp()`.
- Зображення масштабуються в межах контейнера, довгі слова переносяться через `overflow-wrap: anywhere`.
- Навігація й основні дії залишаються доступними на вузьких екранах. DOM-порядок не змінюється через `order` або зворотні напрямки Flexbox.

### Контрольні точки

| Умова | Зміни | Причина вибору |
|---|---|---|
| Менше `42rem` | Одна колонка hero, вертикальне розташування основних блоків | Збереження читабельності на вузькому екрані |
| Від `42rem` — приблизно 672px | Дві колонки hero, пошук і кошик у рядок | Достатньо простору для тексту та картки товару поруч |
| Від `66rem` — приблизно 1056px | Бренд, меню й облікові дії в один рядок | Повна навігація вміщується без стиснення елементів |

Точки переходу обрано за потребами вмісту, а не під конкретні моделі пристроїв. Значення в пікселях наведено для базового розміру шрифту 16px.

## Виправлені проблеми

| Проблема | Виправлення |
|---|---|
| Остання картка неповного flex-рядка розтягувалася на всю ширину | Каталог переведено на Grid, тому картки зберігають однакову ширину колонок |
| На вузькому екрані вкладені відступи надмірно звужували поля | Зменшено mobile-відступи контейнера, форми й fieldset; при 320px ширина поля збільшилася зі 164 до 228px |
| Довге слово в описі картки спричиняло горизонтальне прокручування | Додано перенесення довгих слів і гнучкі обмеження елементів; тестове переповнення усунуто без `overflow-x: hidden` |

## Перевірка

У Microsoft Edge перевірено всі чотири сторінки на ширинах **320, 360, 390, 430, 671, 672, 768, 900, 1055, 1056, 1280 і 1440px**.

Перевірено:

- навігацію, сітку каталогу, форми й кнопки;
- відсутність необґрунтованого горизонтального прокручування;
- довгі назви й описи, порожній каталог і список із 40 карток;
- справжній масштаб браузера **200%** на всіх сторінках;
- клавіатурну навігацію, видимий фокус, Enter, Space та керування radio;
- HTML-валідацію й дані форм;
- `prefers-reduced-motion: reduce`, за якого CSS-переходи вимикаються.

Адаптивні перевірки та перевірки форм завершилися успішно. Фізичні мобільні пристрої та скринридер не перевірялися.

## Форми

Пошук використовує `GET`, а вхід, реєстрація й створення товару — `POST`. Поля мають підписи, підказки, доречні `autocomplete` та вбудовану HTML-валідацію.

Проєкт є статичним: серверні маршрути `api/login`, `api/register` і `api/products` ще не реалізовані. Дані не зберігаються, збіг паролів не перевіряється, пошук не фільтрує каталог. Після надсилання коректно заповненої POST-форми можлива помилка відсутнього маршруту.
